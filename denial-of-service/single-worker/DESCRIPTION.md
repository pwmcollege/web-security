An HTTP request arrives as a stream of bytes. Before the application can handle it, the server needs to read the complete set of request headers. A browser normally sends those bytes promptly, but a client controls when it sends them, and the connection can remain open while the server is still waiting to learn what the client wants.

A synchronous worker handles one request at a time. While it waits for more bytes from its current client, it cannot start serving another. With only one worker, a request that could be answered immediately can sit behind one that has not even finished arriving. The CPU might be mostly idle, and there might be plenty of memory available, but everyone else still has to wait. Keeping that worker occupied lets a slow client deny service while sending very little to nothing traffic.
