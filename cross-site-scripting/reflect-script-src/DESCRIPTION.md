Your input is back in the page body as HTML, but the developer wised up and added a [Content Security Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP). A CSP is the browser's second opinion: a list of what the page is allowed to run, enforced no matter what markup turns up. So this time, injecting a tag isn't the end of the story.

Read the policy and you'll see it never allows `'unsafe-inline'`. That kills an inline `<script>` block and an inline `on...=` handler on the spot, so pasting in a lump of code goes nowhere. But look closer at what it does permit: scripts pulled in by URL, as long as the URL sits on a source it trusts.
